## 几何修复：根因已分解，生产代码尚未改动

隐藏页也参与 QStackedWidget 的最小尺寸计算。公式编辑器有620×600的最小尺寸；
加载的 Quaternion 和 FFT 页也可抬高下限。左栏还存在独立的高度约束，
默认窗口1058×830及恢复几何后没有应用层的可用屏幕/边框容纳保证。
Qt 自身 restoreGeometry 可能做屏幕恢复，不能由此假定所有窗口管理器及 DPI 下的 frame 都可容纳。

隔离 Qt5 offscreen 结构探针将隐藏编辑器/插件页临时滚动包装后，最小尺寸由936×660降到754×624，
请求800×600仍得到800×624。该实验使用 rc.9 实际程序的诊断加载，不是生产修复，也不验证原生边框。
因此不采用只改默认 resize 或降低断言的补丁。后续需同时实现：

1. 在公式/插件页创建阶段使用滚动容器；维持页面映射、信号、插件所有权、关闭销毁和重新打开行为。
2. 左栏在受限高度下可滚动；保留 splitter 宽度与最小化状态、曲线列表和绘图按钮可达性。
3. 布局恢复并激活后按目标 QScreen 的 availableGeometry 和实际 frame margin 约束普通窗口；
   保留最大化/全屏和现有配置格式，覆盖断开的显示器、负原点及超大旧几何。

相应测试必须打开实际编辑器/插件页，验证滚动到底能到达控件、布局保存恢复和插件生命周期，
再在 Linux 有窗口管理器的 X11 及 Windows1600×900的100/125/150/200%逐项检查 frame。
目前未把此问题记作已修复。

## 编译路径和二进制身份：需在依赖构建层修复

rc.9 Mosaico 里最初10条 `.cc` 路径处于 Conan 包缓存，包名前缀与锁定 Abseil 相符，
但这不是具体上游文件的来源证明。新规则共检出25处缓存路径；仍需逐项归因，不能仅改路径摘要便批准。
只给项目主 CMake 加映射不影响已经编进静态依赖的字符串。

后续 Windows 独占空档应先用实际 MSVC19.44做小型编译探针，验证项目源、绝对头文件及生成源的
C/C++ `__FILE__` 结果，再选择有效的源码路径映射。MSVC发布说明提及
[/experimental:deterministic 与 /pathmap](https://learn.microsoft.com/en-us/visualstudio/releases/2022/release-notes-v17.1)，
但这不足以证明该版本下所需映射行为，因此本提案未盲目写入编译开关。

依赖侧要核对每个精确 Conan recipe 是否传递 C/C++ 标志，涵盖 Abseil/OpenSSL 等实际来源，
并使用新的缓存策略避免旧静态库复用。Conan conf 默认不一定改变 package_id，
[官方二进制模型说明](https://docs.conan.io/2/reference/binary_model/extending.html#custom-configuration)
要求需要这种区分时显式考虑配置进入 package_id；不能只换命令参数便推定依赖已重建。
重建后复核原始 DLL、全部异常路径和内容身份；保留原有批准记录与所有反例。

Linux公开测试向量/文档字面量的实际来源证明也不等于新增隐私例外批准。本次不新增绕过规则。

## 安装器语言：有线索，实际二进制根因未闭合

主程序和启动器三语通过不代表 IFW 自身界面已汉化。实际中文桌面下 IFW4.7仍显示英文。
源码 `sdk.pro:30–65` 对带地区语言名的后缀提取及相应 Qt 译文查找存在可疑路径；
`sdkapp.h:209–237` 又先要求 Qt 译文加载，再加载 IFW译文。
这只是源码线索，不能证明官方 installerbase 实际采用了这条构建路径。

下一步应在可用的 Windows 验收空档检查所用 installerbase 的内嵌 qm 资源、准确 IFW版本及实际语言加载，
区分缺资源、locale 回退和打包配置，再选择该 IFW版本支持的额外翻译机制。
不能直接套入应用 Qt5目录、借用4.x界面或修改系统区域设置来掩盖问题。
当前仍作为第三方界面未覆盖项，尚未声称修复。
