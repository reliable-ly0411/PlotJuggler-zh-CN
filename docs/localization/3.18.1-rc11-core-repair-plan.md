# 3.18.1-rc.11 核心修复提案

本提案承接 [Issue #44](https://github.com/reliable-ly0411/PlotJuggler-zh-CN/issues/44) 的固定 rc.10 本机测试。
父提交是 `aa0ecb3459b710f49574008d6b708a33e96bcac7`，Qt5/C++17、真实上游 3.17.2
和现有插件、配置及日志格式契约保持不变。提案未提交时不存在新的受验发布 SHA；不能把父提交的成绩写成 rc.11 已通过。
候选内容改变只将先行号从 rc.10 递增为 rc.11，不改变下游核心版本 3.18.1。

## 固定 rc.10 的实际结果

- Linux ON/OFF 全构建均成功，CTest 各 118/118。Windows ON/OFF 全构建成功，CTest 各 117/118；
  唯一失败是模拟 Linux 路径的测试夹具在 Windows 使用了 `Path`。
- Windows 诊断包动态清单为166项，便携归档与实际安装的166项逐字节一致；`python312.zip` 保留原文件，
  没有额外展开其599项内容。隔离卸载成功，原4条卸载记录、3个快捷方式和36个配置文件未改。
- 三语主程序、启动器及实际 CSV/APBIN 样本、布局回归通过；这不代表所有格式和真实日志均已验证。
  普通 Windows 主窗口仍超出工作区底部9像素，高缩放和800×600也未满足几何要求。
- Windows 严格审计仍拒绝3个未审核的插件身份，以及另外4个含私有路径的插件。
  Linux 本机诊断 tar 的 GnuTLS 公共自测向量、CPython 文档示例仍被旧严格规则拒绝。
  这些原始失败保留，不以新提案的实验结果覆盖。

## 本次集中修复

1. 仅约束普通窗口的外框与可用屏幕；跳过最大化、全屏和最小化状态。
   不重构公式、插件或左栏页面，不修改F10与现有配置格式。新主程序仍须实测，不能仅凭模型判定修复。
2. Windows 路径测试使用 `PurePosixPath`；保留原断言。通知 staging 接受实际 `--build-dir`，
   校验 CMake 明确下载来源，缺必需许可或来源矛盾时报错；`--help` 不再创建同名目录。
3. Arrow 21.0.0与26.0.1仅使用各自SHA固定的源归档、LICENSE和NOTICE，不混用版本。
   已验证源文本也不代表全部传递通知或二进制对应关系完整。
4. Windows C/C++ 源码和依赖构建使用已由真实MSVC及精确OpenSSL Perl模板探针验证的正斜杠路径映射；
   配置进入包身份，旧私有路径依赖不能作为新重建成绩。实际重建、全部产物扫描和新插件身份审核仍待完成。
5. Linux 两类公共字面量的候选记录绑定完整ELF摘要、架构、SONAME、准确来源和完整NUL边界。
   其余秘密、个人路径和联系信息继续检测；改字节、来源、边界或追加敏感内容仍被拒绝。
   新记录是待审差异，不能当作原rc.10包已获批准。

## 优先范围与延期项

按用户允许适当降低要求的指示，优先安装启动、主程序与启动器三语、数据加载、布局、身份隐私及必要许可通知。
七包承诺、同源资产清单和SHA256、严格审计、用户数据保护均不变；未测试平台不能写成通过。

200%及部分150%缩放、800×600小窗口完整适配和最大化偏好恢复仍为已知限制。
普通窗口修复先在实际Windows1600×900和Ubuntu1920×1080的100%及125%环境验证核心控件可达性，
只有新候选实测后才能给出支持结论。严格像素与外框失败须继续单独记录。
IFW自身的全面简繁汉化延期；主程序与启动器三语不受影响。IFW及操作系统原生界面的未覆盖文字须明确列出。
保留已审翻译和完整滚动布局的独立原型，未将其作为本轮已发布功能。
