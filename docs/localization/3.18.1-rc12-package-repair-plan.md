# 3.18.1-rc.12 打包修复提案

本候选延续 Qt5 / C++17 和原有插件、布局及配置契约。下游核心版本仍为 3.18.1，
真实上游仍为 3.17.2；内容变化递增先行号。尚未固定受验提交，也未发布新包。

本轮先汇总此前候选可执行的原生、界面与归档检查，将失败、未测和暂停的安装步骤
分别保留，再集中准备以下修复。内部诊断记录不随包，也不自动公开到 Issue。

- 从指定源码提交读取版本声明，统一收集器的版本、标签与发布说明，拒绝跨候选混用。
- Linux 只处理暂存副本的动态运行库路径和 DWARF；保留原构建与普通符号表，
  复验实际加载及从最终包提取的内容。私有 SDK 缺少系统包元数据时不伪造依赖归属。
- Windows 随包暂存匹配版本的运行库与 IFW 许可文本、来源和必要鸣谢；
  检查必要文件、摘要及安装页副本，换行固定为 LF。材料完整性不替代许可适用性及源码交付。
- 从真实构建环境采集私有根，在任何公共来源记录替换之前扫描；
  对便携 ZIP、固定安装器 EXE 提取的组件和 Linux 最终包分别核对。
  子检查只声明它实际扫描的根与内容，不代替插件身份、秘密材料及其他原有门槛。
- Linux 矩阵实际使用对应 Ubuntu / Debian 容器，保留原生架构、发行版、
  精确源码、六份平台报告和七个软件资产的校验。

OpenSSL 的默认配置目录和公开 compiler 构建信息是两个来源，必须分别消除私有路径。
修改依赖 recipe、锁或公开构建信息时须保留精确来源与完整真实编译参数；
不得修改已编译二进制或把本地构建伪装成 GitHub run。重建后仍需审核实际三个插件身份。

新候选的程序、插件和七个包均须在固定并批准的源码提交上重新构建验收。
原有通过数不能转记到 rc.12；未通过项、实际失败与未运行项必须分开。
安装启动、三语、数据与布局、身份隐私、必要许可证与对应源码继续作为发布条件。
150%/200%、800×600、最大化偏好恢复和 IFW 全面汉化继续列为已知限制。
保留历史版本、用户配置、既有发布与其他版本的工作，不覆盖标签或资产。
